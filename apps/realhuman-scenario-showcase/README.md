# RealHuman 场景产品演示中心

这是 XPADE 人像能力研究的独立 V2 产品化演示，也是与 `realhuman-architecture-lab` 完全分离的场景网页。V1 的源码、页面与线上地址保持不变；本项目只读取一份 R34 生产构建镜像，并将它分别组织为照片、视频和扩展产品入口。

- V1：`https://yydshly.github.io/0831_codex_project/demos/xpade-face-liquify-lab/`
- V2：`https://yydshly.github.io/0831_codex_project/demos/realhuman-scenario-showcase/`
- 发布版本：`2.0.0`

产品总览页新增“完整产品全景”：把照片、摄像头和视频输入，本地实时引擎、生成式大模型、蒙版约束、身份与规格检查以及最终业务场景放在同一张图中。它明确表达当前产品不是提示词集合：本地库负责实时、稳定和确定性处理；生成式模型负责创造原图没有的内容；产品控制层负责任务路由、修改边界和交付质量。

蒙版在生成式链路中采用双重保护：调用模型时提供目标区域，结果返回后再次由本地像素合成强制恢复蒙版外原图。当前 V2 已运行本地蒙版处理，但尚未接入外部生成式图像 API，页面不会把规划能力标为已实现。

`engine/r34/index.html` 是上述页面复用的内部冻结能力引擎，只用于独立调试，不作为第五个用户产品入口。

## 运行

```powershell
npm install
npm run dev
```

- 首页：`http://127.0.0.1:4210/index.html`
- 照片场景：`http://127.0.0.1:4210/photo.html`
- 视频场景：`http://127.0.0.1:4210/video.html`
- 扩展能力：`http://127.0.0.1:4210/extensions.html`

生产构建默认继续使用本机根路径；GitHub Pages 工作流通过 `REALHUMAN_DEPLOY_BASE` 设置独立子路径，并只在构建产物中转换冻结引擎的资源地址，冻结源镜像本身不被修改。

## 能力边界

- 绿色“已实现”：直接加载 R34 冻结能力引擎。
- 琥珀色“底座可用”：共享单人人像能力可运行，但该行业场景的专属流程尚未完成。
- 照片页默认以“企业职业头像”驱动，视频页默认以“视频会议”驱动；进入页面即可看到真实能力，不需要先理解算法。
- 桌面端使用视口级单页工作台：左侧集中场景与路线，右侧直接对齐冻结引擎的实际操作区，不再经过内部项目说明长页。
- “全屏演示”会把右侧能力区进入浏览器全屏；再次点击即可退出并回到原场景状态，“独立打开”保留为调试与深度使用入口。
- 灰色“后期扩展”集中在左侧折叠路线区，只展示需要新增的模型和产品环节，不播放伪造效果，也不会替换当前工作台。
- 扩展能力中心已经提供可真实运行的“老照片基础修复”和“图片风格处理”本地 MVP：可上传、调参、前后比较并导出，不上传图片。
- 图片输入支持原生选择、拖放和剪贴板粘贴；支持 JPG / JPEG / PNG / WEBP，单张不超过 20 MB。页面显示读取状态、文件来源、分辨率与大小；无效输入不会覆盖上一张有效图片。
- 老照片 MVP 只覆盖褪色、偏色、对比、轻噪声和清晰度，不声称完成划痕修补、缺失内容补全、超分或自动上色。
- 图片风格 MVP 是确定性调色，不声称生成服装、发型、背景或新内容。
- 七个扩展模块均提供产品命名的主动作。职业头像、婚纱单人精修、电商单张人像会自动等待真实人脸处理就绪并执行各自不同的模板、参数与输出规格；视频按钮自动运行本地技术流和会议场景，不请求物理摄像头权限。
- 全身试穿的主动作保持禁用，因为人体姿态、服饰分割与试穿生成模型尚未接入；页面不会用基础滤镜伪造试穿结果。
- 一键“基础版本”只证明共享底座步骤真实执行，不等于换装、多人物、商品保护、批处理或会议软件输出已经完成；执行状态会同时列出尚未运行的产品专属能力。
- 职业头像、婚纱和电商一键完成后，扩展页会显示最新结果卡并直接下载冻结底座生成的真实 PNG；职业头像复用底座原有智能裁切输出 1024 × 1024。视频会议完成后可在外层保存当前实时帧 PNG。
- 各产品只在当前页面内存保存一个最新结果，切换模块后返回仍可下载；刷新或关闭页面即清除，不上传、不写入浏览器持久存储。

`public/assets/`、`public/models/` 与 `public/engine/r34/index.html` 是归档构建的本地运行镜像，不应手工修改。后续产品界面开发只修改本项目的 `src/`。

开发工作区另有本地 R34 归档；V2 仓库提交以本目录内的冻结运行镜像为准，不依赖未发布的归档 ZIP。原源码归档 SHA-256 为 `7A8AFDCF0E4083B638A96121C5ED74E4538F601F55026F73063ACF0DBC7E3B05`，原构建归档 SHA-256 为 `06B5D0D78DE1F41657913FD7E4AFD0555AAF233D8C0DBF2F5D94B8A5C547206E`。
