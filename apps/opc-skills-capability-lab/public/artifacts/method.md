# OPC Skills：从通用工具箱到个人创业操作系统

## 我们对这个库的最终理解

OPC Skills 不是一个会自动替用户经营公司的应用，也不是一次搜索后就能给出创业答案的“项目生成器”。它是一套面向一人公司（One Person Company）的 **Agent Skill 探索脚手架**：把需求研究、品牌入口、视觉表达、搜索增长和经验归档拆成 Agent 可以复用的说明、脚本、外部服务适配和工作步骤。

它真正有价值的使用方式是：

```text
获得一套探索方法
→ 用同一套方法研究 3–5 个真实候选项目
→ 保存原始证据、反例和能力边界
→ 横向比较
→ 加入自己的经验、资源、兴趣和用户关系
→ 选择最小现实动作
→ 根据行动结果复盘
→ 改写自己的 Skill、权重、提问和停止条件
```

因此：**仓库提供方法，Agent 提供整理，现实提供反馈，人保留最终判断。**

## 四类判断输入

| 输入 | 回答的问题 | 典型产物 |
|---|---|---|
| 外部证据 | 真实用户和市场正在发生什么？ | 原始链接、时间戳、讨论、竞品、替代方案、失败响应 |
| Agent 整理 | 证据之间有哪些重复、矛盾和机会假设？ | 去重结果、痛点聚类、反例、待验证问题 |
| 个人认知 | 这些事实对“我”意味着什么？ | 用户关系、领域经验、资源优势、兴趣与生活约束 |
| 行动反馈 | 真实访谈或交付是否支持原判断？ | 访谈、落地页、报价、交付记录、复盘结论 |

任何一个输入都不能单独完成决策。讨论热度不等于付费意愿，Agent 评分不等于商业判断，个人兴趣也不能替代真实问题。

## 多项目探索方法

同一轮选择 3–5 个候选项目，并对每个候选使用相同问题：

1. 谁是目标用户？
2. 用户正在完成什么任务？
3. 问题出现在哪里、是否反复出现？
4. 用户现在使用什么替代方案？
5. 是否已经付出时间、人工或金钱成本？
6. 竞品为什么没有完全解决？
7. 自己能否找到并理解这些用户？
8. 最小可证伪动作是什么？
9. 什么结果出现时应该继续、补充探索或停止？

比较的重点不是生成一个看似精确的总分，而是确认：证据强弱、反例、用户可触达性、自身优势和最小验证成本。

## 当前仓库覆盖的需求来源

`requesthunt` 设计上覆盖 Reddit、X、GitHub、YouTube、LinkedIn 和 Amazon；仓库另有独立的 `reddit`、`twitter` 和 `producthunt` Skills。不同来源承担不同任务：

| 来源 | 主要信号 |
|---|---|
| Reddit | 深度抱怨、工作流、替代方案和社区语言 |
| GitHub Issues | 具体 Bug、功能请求和开发者工具缺口 |
| Product Hunt | 竞品、定位、发布方式与公开评论 |
| X | 实时趋势、情绪和从业者观点 |
| YouTube | 教程、评测评论和消费场景 |
| LinkedIn | B2B 角色、企业流程和行业背景 |
| Amazon | 已购买用户的产品缺陷和功能愿望 |

完整需求研究还可以扩展 Hacker News、Stack Overflow、V2EX、知乎、Bilibili、应用商店、G2/Capterra、招聘和服务交易平台。平台越多不一定越好；应根据产品类别选择 2–4 个互补来源，并优先补齐“问题、搜索、竞品、付费”四类证据。

## 十个 Skills 在这套方法中的位置

| 阶段 | Skills | 作用 |
|---|---|---|
| 发现与验证 | `requesthunt`、`reddit`、`twitter`、`producthunt` | 取得并整理公开需求与竞品信号 |
| 品牌入口 | `domain-hunter` | 形成域名候选、价格与购买前检查 |
| 视觉表达 | `nanobanana`、`logo-creator`、`banner-creator` | 生成和处理验证所需的品牌素材 |
| 搜索增长 | `seo-geo` | 审计页面、关键词、SERP 与 AI 搜索可见性 |
| 经验沉淀 | `archive` | 保存判断、失败原因和下一轮可复用知识 |

这些 Skills 可以组合，但仓库目前没有一个成熟的、无人值守的统一创业编排器。外部数据能力通常依赖 API Key、登录、网络访问和第三方服务状态。

## 如何把它变成自己的

真正需要长期积累和修改的是：

- 自己信任的信息源和平台组合；
- 自己判定“证据足够”的门槛；
- 对频率、严重度、付费信号、可触达性和自身优势的权重；
- 自己的用户访谈问题；
- 自己的最小验证动作；
- 明确的停止条件；
- 每次预测与实际结果之间的偏差。

用一次，它是工具；对多个项目重复使用、复盘并改写，它才逐渐成为自己的个人创业操作系统。

## 最近一次真实研究轨迹包含什么

交互主线按本次真实理解过程组织为：想法提出、能力探索、真实取证、认知纠偏和资产沉淀。下列项目内工具运行是支撑这条轨迹的证据层：

- RequestHunt 因缺少项目凭据未执行，页面没有伪装成功；
- 仓库 Reddit 脚本真实返回 HTTP 403；
- GitHub 公共 Issues API 返回 5 条带原始链接的相关问题；
- RDAP 实时检查 3 个域名候选，并区分已注册、未发现记录和不确定；
- 根据前两步证据生成一个最小试探页面与机会简报；
- 仓库 `seo-geo` 脚本真实审计该页面；
- 仓库 `archive` Hook 读取本轮判断和能力边界；
- 六份核心证据文件记录字节数和 SHA-256。

这些记录只证明“一次探索可以被真实执行、纠偏和沉淀”，没有证明市场规模、付费意愿或项目应该继续。下一步应当对其他候选执行同一套方法，再进入人工决策门。
