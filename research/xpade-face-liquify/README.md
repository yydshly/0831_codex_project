## 它实现了什么能力

**[已验证]** 该网页是一款浏览器端、单人脸的 2D 液化工具。Human.js 通过 WebGL 检测一张人脸并返回 468 个关键点；用户调整眼、鼻、嘴、脸宽、下颌和下巴等语义参数，或使用局部推拉工具后，系统把控制点位移传播到图像网格，再用 Canvas 重绘变形结果。

| 能力 | 可观察结果 | 边界 |
| --- | --- | --- |
| 本地载入照片 | 通过 `FileReader` 读取浏览器选择的图片，载入后进入检测与编辑 | `FileReader` 只能证明读取发生在浏览器端，不能单独证明整站完全离线或零网络通信 |
| 单人脸定位 | Human.js / WebGL 返回 468 个面部关键点 | 最多处理一张脸；清晰、近正面的照片更符合当前交互模型 |
| 语义化脸部调整 | 参数被映射为眼、鼻、嘴、轮廓等控制点的目标位移 | 属于几何重映射，不会生成原图中不存在的真实纹理 |
| 局部液化 | 用户可直接推拉局部区域，并查看网格或控制点反馈 | 强形变可能同时牵动头发、背景或局部纹理 |
| 实时预览与比较 | 显示阶段使用 `48 × 48` 网格，可撤销、重做、重置并对照原图 | 预览精度与交互流畅度之间存在取舍 |
| 原尺寸 PNG 导出 | 导出阶段切换到 `96 × 96` 网格并输出 PNG | 更密网格和大尺寸源图会增加计算、显存与内存压力 |

**[已验证]** 它不是换脸、扩散生成或完整人像精修系统；核心效果来自原始像素在三角网格中的重新采样。轻度调整通常保留原照风格，过大的位移则可能出现纹理拉伸、边缘弯曲或背景联动。

## 技术原理速览

已验证的数据流如下：

```text
用户图片
  → FileReader 浏览器读取
  → Human.js / WebGL 单人脸检测
  → 468 个面部关键点
  → 语义控制点与目标位移
  → RBF 将稀疏位移传播到规则网格
  → 网格拆成三角形并求局部仿射映射
  → Canvas 逐三角形重绘预览
  → 96 × 96 网格、原尺寸 PNG 导出
```

预览使用 `48 × 48` 网格以优先保证交互反馈；导出使用 `96 × 96` 网格以减小局部折线感。更完整的公式、模块职责、性能代价与验证点见[技术原理笔记](notes/technical-principles.md)。

| 场景 | 价值 | 结论性质 |
| --- | --- | --- |
| 企业职业头像规范化 | 将轻度人脸几何调整嵌入构图、背景、光线、模板和确认流程，减少集中拍摄与重复制作的产品摩擦 | **[建议]** 产品方向；商业价值、身份保持和处理质量仍需真实用户与图片验证 |

| 人像编辑交互原型 | 语义滑杆、局部画笔、原图比较与导出形成了完整最小流程 | **[已验证]** 页面能力；产品适配程度需另测 |
| 图形学与前端教学 | 同一案例串起关键点检测、RBF、三角剖分、仿射变换和 Canvas | **[推断]**，适合作为教学模型 |

### 不适用或需要谨慎的场景

- **[已验证]** 多人合照：当前最多检测并处理一张脸。
- **[推断]** 专业商业精修：缺少发丝/背景保护、皮肤与光影修饰、精细蒙版和工程文件管理。
- **[已验证]** 移动端优先流程：基线页面在窄屏会出现控件挤压与逐字竖排，操作可用性差。
- **[推断]** 超高分辨率批处理：密网格、逐三角形绘制和大纹理可能造成明显 GPU、内存与导出等待压力。
- **[建议]** 医疗判断、身份识别或“客观审美评分”：几何美化工具不应被包装成诊断或生物识别系统。

## 优点与局限

### 优点

- **[已验证]** 语义参数比直接编辑数百个点更容易理解，同时保留局部推拉的自由度。
- **[已验证]** `48 × 48` 预览与 `96 × 96` 导出体现了交互速度和结果精度的分层策略。
- **[已验证]** 处理链主要位于浏览器，用户选择图片后可即时开始编辑。
- **[推断]** 三角形局部仿射比整图单一变换更适合连续、局部的人脸形变。

### 局限

- **[已验证]** 单脸上限限制了合照和批量工作流。
- **[已验证]** 几何形变无法补全被拉开的真实纹理，强参数容易产生失真。
- **[已验证]** 原站移动端布局未达到稳定可用的响应式体验。
- **[推断]** 固定规则网格未必把算力集中在眼角、嘴角和轮廓等高曲率区域。
- **[推断]** 大图的 WebGL 检测、Canvas 缓冲区和高密网格导出可能同时抬高峰值资源消耗。

## 验证方法

基线结论可按下列步骤复核：

1. 在桌面浏览器打开[上游页面](https://xpade.dothome.co.kr/)，记录日期、浏览器、操作系统和视口。
2. 分别载入清晰单人正面图、无人脸图、双人图和大尺寸图；记录检测数量、失败反馈、首次可编辑时间与峰值资源。
3. 调整每组语义参数，检查目标区域、邻近区域与背景是否连续，并用原图比较确认变化来源。
4. 打开网格/控制点并检查运行时：显示阶段应为 `48 × 48`，导出阶段应为 `96 × 96`。
5. 导出 PNG，比较源图与结果图尺寸、透明度/色彩、边缘接缝以及重复导出的稳定性。
6. 在开发者工具的 Network 面板中，从选择文件到导出完整记录请求；只有这样才能进一步验证“图片是否上传”，不能仅凭 `FileReader` 下结论。
7. 使用 1440 px、768 px 与 390 px 视口复测控件可读性、滚动、焦点顺序和触摸命中区域。
8. 对 1K、2K、4K 图片分别测量检测耗时、拖动帧率、导出耗时、JS 堆与 GPU 资源；据此决定尺寸上限和降级策略。

更细的单元、视觉和性能检查点见[技术原理笔记](notes/technical-principles.md#验证清单)。

## 可复用结论

- 把模型输出转成少量语义控制点，是连接 AI 感知与普通用户编辑行为的关键适配层。
- 用低密度网格交互、高密度网格导出，可以把“手感”和“结果”拆成两个独立预算。
- 局部形变质量不仅取决于检测精度，也取决于位移传播、边界保护、采样和错误恢复。
- “浏览器处理”不自动等于“完全离线”或“绝对隐私”；隐私结论必须由网络审计和依赖部署方式支持。
- 未声明许可证的线上实现只能作为行为与架构研究对象，不能直接视为可复用源码。
