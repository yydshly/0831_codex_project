# 能力、场景与边界

## 硬件与产品形态

**[官方声明]** Microduck 是约 25 cm、约 800 g 以内的小型桌面双足机器人，使用 15 个电机：两腿各 5 个、头颈 4 个，另有 1 个嘴部机构。主控为 RK3566，配置约 1 GB RAM 和 32 GB 存储，并集成摄像头、紧凑型 `8 × 8` ToF、IMU、麦克风/扬声器、NFC、Wi-Fi 和蓝牙等能力。

它的尺寸和算力决定了合适定位：低层运动策略在本机实时运行，较重的视觉、语言或规划能力可由独立进程、局域网主机或云端提供，但必须处理网络断开和安全降级。

## 能力分层

### A. 随实机仓库分发的策略

在研究基线中，`microduck/policies` 包含 9 个 ONNX 文件：

| 能力 | 策略 |
| --- | --- |
| 基础运动 | walk、stand |
| 姿态转换 | sitstand |
| 操作/表现 | ground-pick、left-kick、right-kick、roulade |
| 滚轮模式 | roller、roller-crouch |

这只能证明仓库提供了对应产物。不同硬件批次、地面、电量和标定条件下的成功率仍需实机测试。

### B. 训练仓库中的任务

RL 仓库还提供粗糙地形、swizzle、滚轮斜坡、起身、旋转等环境或配置。它们是继续训练和研究的入口，不应自动列为产品现成功能。

### C. 产品外围能力

- 游戏手柄和 BLE 控制入口；
- 摄像头采集与 WebRTC 视频；
- ToF 和音频服务；
- 设备发现、配置、日志与健康状态；
- OTA 签名验证、启动后健康门禁和失败回滚。

这些能力使 Microduck 更接近一个可持续运行的机器人平台，但路线图中仍有 SDK、移动端、模型交付、远程访问、隐私/校准/诊断等未完成项。

## 它不是什么

### 不是通用具身智能

低层 PPO Actor 的典型输入是本体状态和命令，没有相机图像、语言或通用场景表征。摄像头和 ToF 的存在不等于当前运动策略已经会视觉导航、物体理解或自主决策。

### 不是通用机器人 SDK

机器人模型、关节顺序、电机参数和运行时均针对 Microduck。设计思想可以迁移，但策略和驱动不能无修改套到任意机械结构。

### 不是完整开源硬件

**[官方声明]** 开放重点是软件；机械与电子设计文件没有作为可复刻整机所需的完整 CAD、BOM、原理图和制造资料发布。因此即使软件许可证宽松，也不能据此完整复制硬件。

### 不是所有演示都已量产验证

必须维护以下证据阶梯：

```text
任务配置存在
  < 训练 checkpoint 可复现
  < ONNX 策略已发布
  < 单台实机成功
  < 多台/多环境稳定
  < 产品级持续可用
```

研究和产品陈述应说明自己位于哪一级。

## 使用场景判断

| 场景 | 匹配度 | 说明 |
| --- | --- | --- |
| 机器人 RL / Sim2Real 教学与研究 | 高 | 从执行器、环境、PPO 到 ONNX 和实机运行时链路完整 |
| 新运动技能原型 | 高 | 已有任务框架和稳定关节动作接口，但仍需仿真与实机验收 |
| 桌面陪伴、动作表演、人机交互 | 中高 | 体积、头部/嘴部表现力、音视频和联网能力匹配 |
| 高层 LLM/VLM 机器人 Agent | 中 | 适合把已有技能作为工具；感知闭环、权限和失败恢复需另建 |
| 室内自主导航 | 中低 | 有摄像头和 ToF，但当前资料不是成熟导航栈 |
| 精细抓取 | 低 | 没有通用机械臂/灵巧手，嘴部机构能力有限 |
| 工业搬运、户外、功能安全 | 低 | 尺寸、执行器、传感冗余和认证目标均不匹配 |

## 成熟度判断

| 维度 | 判断 | 原因 |
| --- | --- | --- |
| 研究透明度 | 高 | 训练、执行器建模、任务配置、策略产物和实机运行时均可审查 |
| 低层运动闭环 | 中高 | 已形成仿真—导出—50 Hz 实机执行主链路 |
| 技能丰富度 | 中 | 多个典型动作可用，但不是通用任务学习 |
| 自主感知与规划 | 低 | 相机/ToF 服务与低层策略尚未构成成熟自主闭环 |
| 开发者平台 | 中低 | 路线图仍包含 SDK、移动端、模型通道、远程接入等工作 |
| 硬件可复刻性 | 低 | 软件开放不等于 CAD、电子和制造资料完整开放 |
| 产品稳定性 | 待大规模验证 | 本研究没有多设备、长时间和真实用户环境数据 |
