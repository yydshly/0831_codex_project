# 研究价值与建议

## 核心判断

把这两个仓库概括成“只有机器人和强化学习技能有用，其余没意义”并不准确。它们的价值分为四层：

| 价值层 | 值得研究的内容 | 适合谁 | 深度建议 |
| --- | --- | --- | --- |
| 算法与任务 | PPO、观测、动作、奖励、课程和特权 Critic | 机器人 RL 研究者 | 深入 |
| Sim2Real | 执行器、电源、摩擦、回差、延迟、噪声和随机化 | 控制/仿真工程师 | 深入 |
| 部署工程 | ONNX 契约、50 Hz 循环、滤波、增益、安全和切换 | 机器人平台工程师 | 深入 |
| 产品工程 | 音视频、BLE、日志、健康检查、签名 OTA 和回滚 | 机器人产品团队 | 按需深入 |

它不是基础理论突破，也不是跨领域通用框架；它的突出价值是把许多通常分散在论文、训练仓库、固件和产品服务中的环节放在同一案例里。

## 按我们的目标决定投入

### 如果近期做机器人强化学习

建议优先顺序：

1. 复现一个基础速度任务，确认观测、动作、奖励和 PPO 管线；
2. 理解 BAM 执行器模型和随机化范围的物理含义；
3. 跟踪 normalizer、ONNX 和 Rust 运行时之间的数据契约；
4. 用黄金输入比较训练端和部署端输出；
5. 再修改奖励或新增技能，避免一开始只追求更复杂动作。

### 如果近期做机器人产品或具身智能平台

不必先研究每个 reward term。优先看：

- 策略如何注册、加载、切换和回退；
- `robotd` 如何把实时控制与相机/网络服务隔离；
- 安全状态、健康检查、日志和 OTA 如何约束模型；
- 如何给高层 Agent 提供有限、可确认、可恢复的技能接口。

### 如果近期不做机器人

读完本研究 README 和架构图就足够。可迁移的认识主要是：

- 模型必须有版本化的输入输出契约；
- 训练假设必须显式进入部署和验证；
- 高风险边缘设备需要健康门禁与可回滚升级；
- 演示、可复现权重、实机验证和产品成熟度是不同证据等级。

不建议为了“优秀开源项目”而逐文件学习机器人专用代码。

## 最值得深入的研究问题

1. 哪些 Sim2Real 变量对实机成功率贡献最大，能否用消融实验证明？
2. 执行器模型与域随机化如何根据实机日志自动校准？
3. 61→14 策略 ABI 中哪些隐式参数最容易造成部署漂移？
4. 不同技能如何安全切换，是否需要统一的进入/退出状态和过渡策略？
5. 相机/ToF 高层感知如何与 50 Hz 低层策略以不同频率协作？
6. 如何定义“实机验证”：单次成功、成功率、能耗、电机温度、地面分布和设备数量分别如何计量？

这些问题比继续收集更多炫技动作更有长期研究价值。

## 可执行的扩展路线

### P0：建立可验证基线

- 固定上游提交、依赖和随机种子；
- 复现基础策略的训练、play 和 ONNX 导出；
- 建立观测/动作/normalizer 黄金向量；
- 记录仿真指标与真实机器人指标的对应关系。

### P1：策略包与技能运行时

给每个模型附带 manifest：任务名、版本、关节映射、输入 schema、动作缩放、控制频率、增益、进入/退出条件、硬件兼容和训练 provenance。增加签名、健康探测、灰度发布和平滑回退。

### P2：感知驱动的技能组合

将相机、ToF 和语音放在较低频的感知/规划层，输出受约束的高层意图；低层 PPO 保持 50 Hz 稳定。先做有限状态机或行为树，再考虑通用 Agent。

### P3：数据闭环

收集失败片段和系统状态，做离线标注、仿真重放、随机化校准和回归测试。任何持续学习都应先解决用户同意、隐私、模型回滚和安全评估。

## 何时停止深入

出现以下情况时，继续研究的边际收益通常较低：

- 没有 Microduck 或相似硬件，也不准备做机器人仿真；
- 目标只是调用一个现成动作，而不是修改或验证策略；
- 项目需要工业级认证、负载或精度，硬件方向本身不匹配；
- 真正问题在高层视觉/语言产品，而非运动控制和设备运行时；
- 无法满足模型资产的许可要求。

此时应把本项目保留为参考案例，而不是技术栈依赖。

## 一句话定位

**Microduck 是值得按目标研究的机器人全栈优秀案例：对 RL/Sim2Real 和机器人产品工程有较高价值，对非机器人方向则以理解架构和证据边界为主，不必深挖。**
